# Arch Linux (AUR)

| Package | Built from |
|---|---|
| `sinden-driver-bin` | the driver's static binary of the release pinned in `driver.lock` |
| `sinden-driver-ui` | this repository's source at tag `v<version>` |

The UI is packaged from source rather than as `sinden-driver-ui-bin`: it
is free software, and it links against the system's WebKitGTK, so a binary
built on Ubuntu could break with Arch's libraries.

The PKGBUILDs here are templates. `scripts/build-aur` renders them into
`dist/aur/<package>/` with:

* `pkgver` from `driver.lock` (driver) or `ui/package.json` (UI);
* the per-architecture `sha256sums` of the driver from `driver.lock`, and
  those of the support files (default configuration, NOTICE), copied next
  to the PKGBUILD;
* the UI's source tarball checksum, when the tag already exists on GitHub;
* `.SRCINFO`, generated by `makepkg --printsrcinfo` (on Arch) or, without
  makepkg, in an `archlinux:base-devel` container (Docker).

Publishing (maintainer, with an AUR account):

```sh
scripts/build-aur
git clone ssh://aur@aur.archlinux.org/sinden-driver-bin.git aur-sinden-driver-bin
cp dist/aur/sinden-driver-bin/* aur-sinden-driver-bin/
cd aur-sinden-driver-bin && git add -A && git commit -m "Update to X.Y.Z" && git push
```

`package()` installs the systemd unit, udev rule, sysusers.d and
tmpfiles.d entries and the hwdb by running the downloaded driver natively:
`sinden-driver service files --bin /usr/bin/sinden-driver --dir "$pkgdir"`.

pacman's own hooks then create the user, apply the tmpfiles.d entries,
update the hwdb and reload udev (with `udevadm trigger -c change`), on
install, upgrade and removal.

Unlike the deb and rpm packages, `sinden-driver-bin` does not enable the
service by itself (Arch's convention): `systemctl enable --now
sinden-driver.service`.
